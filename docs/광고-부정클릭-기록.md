# 네이버 검색광고 부정클릭 기록

세무회계 경우 (kwootax.co.kr)

이 문서는 네이버 **무효클릭 문의하기** 접수와, 필요할 경우 법률 상담에
가져갈 자료를 한곳에 모아 둔 것이다. 공개되지 않는다 (`.vercelignore`로 배포 제외).

---

## 0. 먼저 — 이것이 "봇 공격"이라고 단정할 수 없다

지금까지 본 숫자는 **두 가지로 다 설명된다.**

1. **콘텐츠 매체 노출.** 퀵스타트는 검색 결과만이 아니라 네이버 안팎의
   콘텐츠 지면에도 광고를 깐다. 지면 광고는 원래 노출이 수만 건 나오고
   클릭률이 0.3% 수준으로 낮으며, 실수로 눌린 클릭이 많아 전환이 거의 없다.
   **이건 범죄가 아니라 광고 상품이 원래 그런 것이다.**
2. **의도적인 반복 클릭.** 경쟁 사무소나 자동화 프로그램이 광고를 눌러
   예산을 태우는 행위. 이쪽이면 업무방해에 해당할 수 있다.

**둘을 가르는 것은 IP다.** 같은 IP가 짧은 시간에 반복해서 들어왔다면 2번이고,
서로 다른 IP가 한 번씩 스쳐갔다면 1번이다. 그 IP를 우리는 지금 갖고 있지 않다
(아래 2장).

1번인데 2번이라고 신고하면 접수가 반려되고, 고소까지 가면 무고 문제가 생긴다.
**순서는 (1) 자료 확보 → (2) 네이버 재검토 요청 → (3) 결과를 보고 법률 상담**이다.

광고주센터 화면에서 읽은 값이다. 원본 캡쳐는 따로 보관할 것.

| 항목 | 값 |
|---|---|

| 총 클릭 | 약 117회 (총비용 ÷ 평균 CPC로 역산) |
| 전환 | **0건** |
| 광고 연결 URL | 구 vercel.app 주소 (현 kwootax.co.kr 아님) |

### 키워드별 이상치

| 키워드 | 노출 | 클릭률 | 비고 |
|---|---|---|---|
| 미용실전문세무사 | 33,511 | **0.30%** | 전체 노출의 98%, 클릭의 96% |
| 미용실세무사 | 34 | 5.88% | 정상 범위 |
| (그 외) | 소수 | 7.14% | 정상 범위 |

`미용실전문세무사`는 실제 검색량이 거의 없는 말인데 노출이 33,511건 나왔다는
것 자체가, 사람이 그 말을 검색해서 본 게 아니라는 뜻이다.

## 2. 왜 과거 클릭의 IP를 못 구하는가

네이버 무효클릭 문의는 네 가지를 요구한다.

```
클릭 일시 · 유입 IP · 광고가 노출된 키워드 · 광고주 URL
```

이 중 **유입 IP**를 우리는 갖고 있지 않다.

- GA4와 Clarity는 **설계상 IP를 저장하지 않는다.** 개인정보라 수집 단계에서 버린다.
- 사이트에 서버 접속 로그가 없었다. 정적 페이지라 기록이 남지 않는다.
- 광고 기간(7일)에는 측정 도구 자체가 아예 없었다.

따라서 **지난 237,810원어치 클릭의 IP는 복구 불가능하다.**
그 기록을 가진 곳은 네이버뿐이다.

### 그래도 할 수 있는 것

네이버는 자체 필터링으로 무효클릭을 걸러 **과금하지 않고 보고서에서도 뺀다.**
즉 이미 일부는 빠졌을 수 있다. 남은 길은 **재검토 요청**이다.
IP 없이 접수하되, 위 1장의 키워드 이상치를 근거로 제출한다.

- 접수처: 네이버 검색광고 → 고객센터 → 무효클릭 문의하기
- 제출할 것: 기간, 캠페인명, 키워드별 노출·클릭·비용 보고서, 전환 0건 사실,
  그리고 "노출의 98%가 한 키워드에 몰리고 그 키워드만 CTR이 0.30%"라는 점

광고 보고서는 광고주센터에서 **직접 내려받아야 한다** (나는 naver.com에
접근이 차단되어 있다). 보고서 → 다운로드 → 기간 지정 → 키워드별 상세.

## 3. 지금부터 쌓이는 기록

2026-11-17부터 `api/t.js`가 방문 한 건마다 다음을 적는다.
광고를 다시 켜면 그때부터는 IP가 남는다.

**서버가 직접 읽는 값** (브라우저가 속일 수 없다)

```
접속 IP · User-Agent · 접속 국가/도시 · 서버 시각(UTC/KST)
```

**브라우저가 보고하는 값** (참고용)

```
체류 시간 · 클릭 수 · 마우스 이동 수 · 최대 스크롤 % · 시간대
화면 크기 · CPU 코어 수 · 언어 설정 · 터치 지원 · navigator.webdriver
```

**자동 판정.** 아래 신호에 점수를 매겨 합산한다. 하나만으로 단정하지 않는다.

| 신호 | 점수 |
|---|---|
| 자동화 도구 User-Agent (HeadlessChrome, Puppeteer, curl 등) | 4 |
| `navigator.webdriver = true` | 4 |
| User-Agent 없음 | 3 |
| 클릭·마우스이동·스크롤이 전부 0 | 3 |
| 광고 파라미터는 있는데 referrer 없음 | 2 |
| 체류 1.5초 미만 | 2 |
| `navigator.languages` 비어 있음 | 2 |
| 모바일 UA인데 터치 미지원 | 2 |
| 화면 크기 읽기 실패 / CPU 코어 0 / 시간대 불일치 | 각 1 |

**광고로 들어온 방문이 5점 이상**이거나 **같은 IP가 1시간에 5회 이상**이면
상담 접수와 같은 주소로 메일이 간다. 메일은 네이버 접수 양식 그대로
(클릭 일시 · IP · 키워드 · 광고주 URL) 정리돼서 온다. **지우지 말 것.**

자연 유입은 점수가 높아도 메일을 보내지 않는다. 사람도 1초 만에 뒤로 가기를
누르기 때문에, 광고비가 걸린 건만 알린다.

### 전수 기록을 보는 법

Vercel → 프로젝트 `kwootax-landingpage-86cn` → Logs에서 `HITLOG` 검색.
한 줄에 JSON 한 건이다.

Vercel 무료 요금제는 로그를 길게 보관하지 않으므로, 오래 남는 저장소를
따로 붙였다.

### 장기 보관 — Upstash Redis `kwootax-hitlog` (2026-11-17 연결)

서버 위치는 도쿄(nrt1). 무료 플랜, 월 50만 명령. 용량이 차도 오래된 기록이
밀려나지 않게 Eviction은 껐다.

| 키 | 담는 것 |
|---|---|
| `hits:YYYY-MM-DD` | 그날 방문 전체. 한 줄에 JSON 한 건 |
| `ipcnt:<IP>` | 그 IP의 최근 1시간 방문 횟수 |
| `repeat:YYYY-MM-DD` | 그날 2회 이상 들어온 IP와 횟수 |
| `botmail:<IP>` | 알림 메일 중복 방지용 (1시간) |

보관 기간은 **365일**로 걸어뒀다. 처리방침에 적은 "접속 기록 1년"과 같은
값이어야 한다. 한쪽만 고치면 안 된다.

보는 법: Vercel → Storage → kwootax-hitlog → Browser.
`repeat:` 키를 먼저 보면 된다. 같은 IP가 반복해서 들어왔는지가 봇 공격과
콘텐츠 매체 오클릭을 가르는 지점이다 (0장).

**2026-11-17자 기록 앞부분에 동작 확인용 가짜 방문 4건이 들어 있다.**
키워드가 `redis-verify-0/1/2`와 `claude-verify`로 찍혀 있다. 실제 방문이
아니다.

### 개인정보처리방침이 먼저다

현재 사이트 하단의 "개인정보처리방침" 링크는 `#contact`를 가리킨다.
**방침 문서가 없다.** 상담 폼에서 이름·연락처를 받고 있고, 이제 접속 IP까지
기록하므로 수집 항목과 보유 기간을 적은 방침이 있어야 한다.

IP 수집 자체는 부정이용 방지 목적이면 일반적으로 인정되는 범위지만,
**"무엇을 왜 얼마나 보관하는지" 고지는 빠질 수 없다.** 내가 초안을 쓸 수 있다.
다만 사무소 사정(보유 기간, 위탁 업체, 책임자)은 사장님이 정해야 한다.

### 고소를 검토할 때

형사 고소(업무방해)는 **가해자가 특정돼야** 실익이 있다. 우리가 모은 IP는
출발점이고, 그 IP가 누구인지는 통신사 기록이라 수사기관만 열 수 있다.
그리고 네이버가 가진 클릭 로그가 결국 핵심 증거가 된다.

나는 세무사도 변호사도 아니다. **고소 여부와 죄명 판단은 변호사와 상의할 일**이다.
내가 할 수 있는 건 위 자료를 사실관계 그대로 정리해 두는 것까지다.
